# V4: result, flow, design

V4 keeps the analysis of V3 (detection, tracking, counting rules: [V3-archive.md](V3-archive.md)) and rebuilds what the user sees. Desktop only (from 1280 px; checked at 1440×900 and 1920×1080). Over-counting after an occlusion stays acceptable: a re-appearance is a new impression.

## What it is

- **Flow:** start screen (title, intro) → one viewport down, two round buttons (Photo / Video, Camera) → analysis page. The arrow at the top left ends a running camera, clears the input and scrolls the start screen to the options (`#choose`).
- **Analysis page:** the media box (the picture is scaled to fit, up or down), a compact bar under it (video: play/pause, seek; camera: pause, stop), and three elements on the right: the result button, the model status with the class selection, the gear. A file dropped on the box replaces the input; on the start screen a file dropped on the Photo / Video button loads it.
- **Result:** a pop-up of about 85% of the viewport, sliding in from the top, with a D3 treemap of the totals per class (area = count, labeled "People 22"). It follows the totals live (camera and video), draws only while open, and never touches the analysis. Reset counts is in its header.
- **Settings:** a pop-up at the bottom right (threshold, model, advanced, debug, reset to defaults; the camera choice when there are two or more).
- **Design:** tokens in [tokens.css](../src/styles/tokens.css): the given type scale, 60% off-black, 30% off-white and grays, 10% accents ([palette.ts](../src/rendering/palette.ts) mirrors them; a test keeps both in step). The ground is flat dark with a fine static grain (tiled SVG noise in the `html` background) and, faintly, the stroke colors shining in from the window edges (`body::before/::after`, `--edge-light` opacity), with a weak "flashlight" around the pointer ([spotlight.ts](../src/ui/spotlight.ts), one element moved by a transform). Buttons have no fill color: on hover or focus a thin, saturated stroke shows, an animated accent gradient cut out by a mask (a different gradient per kind of button; `--stroke-*` in [main.css](../src/styles/main.css); no WebGL, the GPU belongs to inference). Glass panels blur only beside the picture; pop-ups have a nearly opaque fill because they lie over it. Buttons are icons ([icons.ts](../src/ui/icons.ts)).

## Removed

- **Pre-analysis** (WebCodecs, cache, state machine) and with it `mediabunny`, its notices, `e2e:pre`: the new flow has no second video mode.
- **"Current frame"**: commented out everywhere (marked "disabled in V4"), including the detection of the paused frame and its checks. Without it a paused or just-loaded video shows no boxes of its own until it plays. To bring it back: uncomment the marked blocks in `App.ts`, `RealtimeVideo.ts`, `CountsPanel.ts` and the e2e scripts.

## Performance (production build, M4 Max, headless Chrome, plugged in)

| measurement                                          | V3 (Phase 0)        | V4                             |
| ---------------------------------------------------- | ------------------- | ------------------------------ |
| realtime inference fps (YOLOv8s / n on WebGPU, WASM) | 30.0–30.1, 0% drops | 30.1, 0% drops (WASM too)      |
| round trip p50, YOLOv8s on WebGPU                    | 12.0–12.9 ms        | 12.2–12.3 ms                   |
| main-thread time, `moving_car`, dialog closed        | 21.4 ms/s           | 23.0 ms/s (+1.6)               |
| main-thread time, result dialog open                 | –                   | 34.8 ms/s (+11.8 over closed)  |
| first visit at 50 Mbit/s / reload                    | 8.55 s / 0.33 s     | 8.37 s / 0.38 s                |
| `dist/`                                              | 82 MB               | 82 MB (Vercel Hobby limit 100) |

The open dialog costs about 3.5 ms per update of the totals (3.4 a second), with no long task and no change in fps. The cost came from animating tile sizes (a layout every frame): the treemap now redraws at most four times a second, animates over 300 ms, and a tile that moves less than 24 px snaps. An open dialog went from 45.8 to 34.8 ms/s that way. The remainder is layout and paint of the tiles. WASM at the 30 fps cap ran 24–25 fps in the first V4 baseline run only because the laptop was on battery.

## Checks

`npm run e2e | e2e:video | e2e:counts | e2e:webcam | e2e:keys | e2e:walk | e2e:contrast -- --build` (the webcam check "resume" is intermittent: it sometimes finds 0 of the ~17 confirmed tracks again after the 3 s pause, in 1 of 9 runs on the V3 code and 3 of 14 on V4, and otherwise 4–7, which sits at its 25% limit; the cause is not found and it predates V4): image counts, realtime, totals, camera (with the treemap), keyboard (Tab order, focus rings, both pop-ups, focus return), the full walk at two sizes with screenshots, and the text contrast measured against what is really behind it. `node scripts/e2e/mainThreadCost.ts` measures the main-thread cost.

## Not verified

Real camera (only Chrome's fake one), two real cameras, Safari and Firefox, long sessions (memory, heat), the pop-up animations in between (end states only), a real file drag (unit-tested with simulated events), weaker GPUs.

Done so far (uncommitted, on branch `V4`): background reworked (flat dark with grain, pointer spotlight, faint edge light in the stroke colors), button strokes (thin saturated animated gradients, one per button kind, shown on hover/focus), `overscroll-behavior: none` on `html` (rubber-band at the top; not testable headless, the user should confirm).
